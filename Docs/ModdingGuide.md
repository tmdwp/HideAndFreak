# Hide&Freak 모드 제작 안내

이 문서는 Hide&Freak에 새 **맵**과 맵에서 쓰는 **캐릭터 외형**을 모드로 추가하는 방법을 설명합니다.
모드 SDK(`HideAndFreak_ModSDK_<버전>.unitypackage`)와 함께 배포됩니다.

## 1. 모드로 할 수 있는 것

| 할 수 있는 것 | 설명 |
|---|---|
| 새 맵 | 맵 모델, 스폰 지점, 전원 장치 후보, 변신 가능 사물, 조명 |
| 맵별 캐릭터 외형 | 그 맵에서 마네킹(가짜 마네킹 포함)·가드가 쓸 모델과 애니메이션 |
| 맵별 룸 설정 | 맵을 고르면 적용되는 기본값과, 호스트가 고를 수 있는 범위 (시간, 체력, 속도 등) |
| 맵별 인원 | 이 맵을 플레이할 수 있는 최소·최대 인원 |
| 맵 이름 번역 | 한국어·영어 등 게임이 지원하는 언어 |

| 할 수 없는 것 | 이유 |
|---|---|
| 코드(스크립트) 추가 | 모드 파일(AssetBundle)은 코드를 담을 수 없습니다. 게임에 들어 있는 컴포넌트만 쓸 수 있습니다. 보안상 장점이기도 합니다. |
| 게임 규칙·도구 변경 | 총, 수류탄, 변신 같은 동작은 게임이 정합니다. 수치는 맵별 룸 설정의 범위 안에서만 바꿀 수 있습니다. |
| 게임 문장 덮어쓰기 | 모드 번역은 `mod.<모드 ID>.`로 시작하는 문장만 추가할 수 있습니다. |

## 2. 준비: 모드 제작 프로젝트 만들기

### 2.1 필요 환경

SDK 폴더의 `requirements.txt`를 먼저 확인하세요. 예시는 다음과 같습니다.

```
Unity 버전: 6000.4.0 ~ 6000.4.2f1 (같은 6000.4 라인, 게임 이하. 게임보다 새 버전은 안 됨)
  권장: 6000.4.2f1 (게임과 같은 버전)
렌더 파이프라인: URP
패키지:
  - com.unity.render-pipelines.universal 17.4.0
  - com.unity.ai.navigation 2.0.12
빌드 대상: Windows (StandaloneWindows64)
```

> **Unity 버전 규칙:** 게임과 **같은 메이저·마이너 라인**(예: `6000.4`)이고, 게임과 **같거나 더 옛 패치**여야 합니다.
>
> | 모드를 만든 Unity | 게임 6000.4.2f1에서 |
> |---|---|
> | 6000.4.0f1, 6000.4.2f1 | ⭕ 사용 가능 |
> | 6000.4.3f1 (게임보다 새 버전) | ❌ 게임이 읽지 못함 |
> | 6000.3.x, 6000.5.x (다른 라인) | ❌ 셰이더가 깨지기 쉬워 막음 |
>
> 가장 안전한 것은 게임과 **정확히 같은 버전**입니다. 규칙에 맞지 않는 버전으로는 모드 내보내기가 거부되고, 게임에서도 로비 모드 화면에 오류로 표시됩니다.
>
> 게임이 Unity 라인을 올리면(예: 6000.4 → 6000.5) 그때는 모드를 새 SDK로 다시 내보내야 합니다.

### 2.2 프로젝트 만들기

1. Unity Hub에서 `requirements.txt`의 버전을 설치하고, 템플릿 **Universal 3D (URP)** 로 새 프로젝트를 만듭니다.
2. **Window > Package Manager** 에서 `requirements.txt`의 패키지를 같은 버전으로 설치합니다. 특히 **AI Navigation**이 필요합니다.
3. **File > Build Profiles** 에서 플랫폼을 **Windows**로 바꿉니다. 내보내기는 Windows용으로 하므로, 바꿔 두면 내보내기가 빨라집니다.
4. **Assets > Import Package > Custom Package** 로 SDK 패키지를 가져옵니다.

가져오면 다음이 생깁니다.

| 폴더 | 내용 |
|---|---|
| `Assets/_Project/Content` | 맵·사물·외형 컴포넌트 (`MapInfo`, `SpawnPoint`, `GeneratorSpawnPoint`, `TransformableProp`, `MapLight`, `CharacterSkin` 등) |
| `Assets/_Project/ContentEditor` | 맵 도구, 맵 검사, 모드 설정, 모드 내보내기 |
| `Assets/_Project/ModSdk/Settings` | 게임과 같은 그래픽(URP) 설정 |
| `Assets/_Project/ModSdk/Template` | 예제 모드 (예제 맵 씬, 예제 모드 설정, 번역 파일) |

5. **GameSettingTools > 모드 제작 > 게임 그래픽 설정 적용** 을 한 번 실행합니다.
   - 모드 번들의 셰이더는 제작 프로젝트의 그래픽 설정으로 만들어집니다. 게임과 설정이 다르면 게임에서 재질이 분홍색이거나 빛이 이상하게 보일 수 있습니다.
   - 적용하지 않고 내보내면 내보내기 도구가 적용할지 묻습니다.

메뉴에 **Hide&Freak** 가 생기면 준비가 끝난 것입니다.

### 2.3 예제 모드로 먼저 해 보기 (권장)

1. `Assets/_Project/ModSdk/Template/ExampleModProject` 를 선택합니다.
2. 인스펙터의 **Copy To Mods Folder**에 게임의 `Mods` 폴더 경로를 적습니다.
3. **GameSettingTools > 모드 제작 > 모드 내보내기 (선택한 Mod Project)** 를 실행합니다.
4. 게임을 켜고 로비의 **모드** 화면에서 `Example Template`이 `[켜짐]`인지 확인합니다.
5. 방을 만들고 맵으로 **예제 맵**을 골라 플레이합니다.

여기까지 되면 환경 준비는 끝났습니다. 자기 모드는 예제 씬(`Example_TemplateMap`)과 예제 모드 설정을 복사해서 시작하면 편합니다. 복사하면 **Mod Id와 씬 이름을 반드시 바꾸세요.** 예제와 같은 ID·씬 이름으로 배포하면 다른 사람의 예제 모드와 충돌합니다.

## 3. 맵 만들기

### 3.1 순서 한눈에 보기

```
새 씬 → 맵 뼈대 → 모델 배치 → 충돌체 → 변신 사물·벽 등록 → 조명 등록
      → 지점 배치 → NavMesh 굽기 → 대기 화면 위치 → 맵 검사 → (6장) 내보내기
```

메뉴는 모두 **GameSettingTools > 모드 제작 > 맵 도구** 아래에 있습니다.

### 3.2 맵 뼈대 만들기

1. **File > New Scene** 으로 빈 씬을 만들고 저장합니다. 씬 이름이 게임 안 씬 이름이 되므로, **다른 모드와 겹치지 않게** 정합니다. (예: `MyName_Basement`) 게임에 들어 있는 씬(`Lobby`, `Room`, `Game_Systems`, `Map_Asylum` 등)과 같은 이름은 내보내기에서 막히고, 게임도 그 모드를 쓰지 않습니다.
2. **맵 도구 > 맵 뼈대 만들기 (열린 씬)** 을 실행합니다.

다음 구조가 만들어집니다.

```
Map                      ← MapInfo(맵 정보), NavMeshSurface(가짜 마네킹 길)
├─ Environment           ← 맵 모델을 여기에 넣습니다
├─ MannequinSpawnPoints
├─ GuardSpawnPoints
├─ GeneratorSpawnPoints
├─ Lights
└─ CameraOverview        ← 대기·결과 화면 카메라 위치
```

### 3.3 모델 배치

- 맵 모델(바닥, 벽, 가구 등)을 **`Map/Environment` 아래**에 넣습니다.
- 크기는 **사람 키 1.8m 기준**입니다. 문 높이 약 2m, 의자 높이 약 0.45m를 기준으로 맞추세요.
- 머티리얼은 **URP Lit** 등 기본 URP 셰이더를 쓰세요. 다른 셰이더는 게임에서 분홍색으로 보일 수 있습니다.
- 맵 바깥으로 나가지 못하도록 **투명한 경계와 천장**을 만드세요.
  - 빈 오브젝트에 Box Collider만 붙이면 됩니다.
  - 마네킹은 벽을 타고 오를 수 있어서 천장이 없으면 맵 밖으로 나갈 수 있습니다.
- `MapInfo`의 **Ceiling Height**에 바닥에서 천장(또는 투명 천장)까지의 높이를 적습니다. **100m보다 낮아야** 합니다.

### 3.4 충돌체 추가

- 걸어 다닐 바닥, 벽, 사물을 선택하고 **맵 도구 > 선택 → 충돌체 추가** 를 실행합니다.
- 충돌체가 없는 물체는 플레이어가 통과하고, 가짜 마네킹도 그 위를 다니지 못합니다.

### 3.5 변신 사물과 벽 등록

| 메뉴 | 대상 | 변신하면 |
|---|---|---|
| **선택 → 변신 사물로 등록** | 의자, 상자, 화분, 책장 등 | 그 물체의 메시·머티리얼·크기·기울기 그대로 |
| **선택 → 벽으로 등록** | 큰 벽 | 1.2 × 2 × 0.25m 벽 조각 (첫 번째 머티리얼) |

- 여러 조각으로 된 가구는 **부모 오브젝트를 선택**해서 등록하세요. 그래야 통째로 변신합니다.
- 자세한 규칙은 [4장](#4-변신-사물-규칙)을 보세요.

### 3.6 조명 등록

- **맵 도구 > 모든 조명 등록** 을 실행합니다.
- 모든 조명이 **사냥 시간에 꺼지는 조명(MapLight)** 이 되고, 실시간 조명으로 바뀝니다.
- **구운(Baked) 조명은 쓰지 마세요.** 구운 빛은 사냥 시간에도 꺼지지 않습니다.
- 사냥 시간에는 맵 전체가 어두워지고, 가드의 손전등과 마네킹의 좁은 시야만 남습니다. 이 상태로도 플레이가 되는지 생각하며 조명을 배치하세요.

### 3.7 지점 배치

씬 뷰에서 지점을 놓을 곳을 화면 가운데로 맞추고 **맵 도구 > 지점 추가** 에서 고릅니다. 화면 가운데 아래 바닥에 지점이 생깁니다. 이동 도구(W)로 옮기고 회전 도구(E)로 방향을 정하세요.

| 지점 | 권장 수 | 설명 |
|---|---|---|
| 마네킹 스폰 | **9개 이상** | 판 시작 위치입니다. 가짜 마네킹도 이 주변 약 4m에 흩어져 나옵니다. |
| 가드 스폰 후보 | 5개 | 게임이 판마다 이 후보와 바닥 무작위 위치 중에서 고릅니다. 고르는 기준은 마네킹 스폰에서 **20m 이상** 떨어지고 마네킹 스폰이 **직접 보이지 않는** 곳입니다. |
| 전원 장치 후보 | **12개** | 마네킹이 파괴하는 목표입니다. 매 판 서로 멀리 떨어진 후보가 골라집니다. 맵 곳곳에 넓게 퍼뜨리세요. |

- 지점은 반드시 **걸어서 갈 수 있는 바닥** 위에 두세요. 지붕 위나 막힌 방에 있는 가드 후보는 쓰이지 않습니다.
- 씬 뷰에서 노란 구는 마네킹 스폰, 하늘색 구는 가드 스폰 후보, 빨간 상자는 전원 장치 후보입니다.

### 3.8 NavMesh 굽기

1. `Map` 오브젝트를 선택합니다.
2. **NavMesh Surface** 컴포넌트의 **Bake** 를 누릅니다.

- NavMesh는 가짜 마네킹이 돌아다닐 길이고, 가드 스폰 위치를 고르는 데도 쓰입니다.
- 게임은 모드 맵의 NavMesh를 실행 중에 다시 구울 수 없으므로 **반드시 미리 구워야** 합니다. 굽지 않으면 맵 검사에서 오류가 납니다.
- 맵을 고친 뒤에는 다시 구우세요.

### 3.9 대기 화면 위치

- `Map/CameraOverview`를 맵 전체가 잘 보이는 곳으로 옮기고 아래를 내려다보게 돌립니다.
- 대기 화면과 결과 화면에서 카메라가 이 위치에 있습니다.
- 씬 뷰를 원하는 각도로 맞춘 뒤 `CameraOverview`를 선택하고 **GameObject > Align With View** 를 쓰면 편합니다.

### 3.10 맵 검사

**맵 도구 > 맵 검사 (열린 씬)** 을 실행하고 Console을 봅니다.

- **빨간 오류**는 반드시 고쳐야 합니다. 오류가 있으면 내보낼 수 없습니다.
- **노란 경고**는 동작은 하지만 확인이 필요한 것입니다.
- 오류·경고를 누르면 해당 오브젝트가 선택됩니다.

### 3.11 맵 씬에 넣지 말아야 할 것

| 넣지 말 것 | 이유 |
|---|---|
| 카메라, AudioListener | 게임이 씬 카메라를 붙입니다. 두 개가 되면 화면이 꼬입니다. |
| Canvas, EventSystem 등 UI | 게임 HUD와 겹칩니다. |
| 다른 패키지의 스크립트 컴포넌트 | 게임에 없는 스크립트는 "Missing Script"가 되어 동작하지 않습니다. |
| 구운 조명, Reflection Probe 굽기 | 사냥 시간 연출과 맞지 않습니다. |

## 4. 변신 사물 규칙

마네킹이 물체를 조준하고 우클릭하면 그 물체로 변신합니다. 게임은 **조준한 물체의 모습을 그대로 복사**하므로, 따로 모델을 준비할 필요가 없습니다.

| 규칙 | 설명 |
|---|---|
| 크기 | 가장 긴 변이 **3m 이하**인 물체만 변신할 수 있습니다. 더 크면 조준해도 외곽선이 뜨지 않습니다. 큰 벽은 "벽으로 등록"을 쓰세요. |
| 여러 조각 | 부모에 등록하면 자식 조각까지 모두 복사됩니다. 자식에 따로 등록된 것은 부모에 등록할 때 합쳐집니다. |
| 충돌체 | 조준하려면 충돌체가 필요합니다. 등록할 때 없으면 자동으로 붙습니다. |
| 정적 배칭 | 변신 사물은 정적 배칭(Static Batching)을 끕니다. 등록할 때 자동으로 꺼집니다. 켜져 있으면 모습이 깨집니다. |
| 복사되지 않는 것 | 파티클, 조명, 스킨 메시(애니메이션 모델)는 복사되지 않습니다. 이런 것이 달린 물체(촛불, 선풍기 등)는 변신 모습이 원래와 달라 보여 가드에게 들킵니다. 등록하지 않는 것을 권장합니다. |
| LOD | 가장 자세한 단계(LOD0)만 복사됩니다. |
| 번호 | 사물 번호는 씬을 저장할 때와 내보낼 때 자동으로 매겨집니다. 인스펙터의 Index는 직접 바꾸지 마세요. |
| 판마다 배치 섞기 | 게임은 판마다 **크기가 비슷한 변신 사물끼리 자리를 바꾸고**, 조금 옮기고 돌립니다. (벽으로 등록한 것은 그대로) 그러니 변신 사물은 어느 자리로 옮겨져도 어색하지 않은 물체로 고르고, 오클루전(Occluder/Occludee Static)은 켜지 마세요. 켜 두면 옮긴 뒤 엉뚱하게 사라질 수 있습니다. |

변신하면 물체는 **마네킹이 바라보는 방향**으로 놓입니다. 기울기(눕힌 물체 등)는 원래대로 유지됩니다.

등록하면 안 되는 것:
- 천장, 바닥
- 조명 기구
- 전원 장치 후보 주변 1.5m 안의 구조물

## 5. 캐릭터 외형 (선택)

맵마다 마네킹과 가드의 모습을 바꿀 수 있습니다. 바꾸지 않으면 게임 기본 외형(마네킹 더미, 가드 Ethan)을 씁니다.
사냥 시간이 되면 마네킹은 **사냥 외형**으로 바뀝니다. 맵이 사냥 외형을 지정하지 않으면 게임 기본 사냥 외형(Ghoul)을 씁니다.

### 5.1 모델 준비

- 모델 프리팹은 **발이 원점(0,0,0)**, **정면이 +Z** 여야 합니다.
- 사람형은 Rig를 **Humanoid**로 설정하면 애니메이션을 다루기 쉽습니다.
- 모델에 스크립트·충돌체는 넣지 마세요. 게임 캐릭터가 이미 갖고 있습니다.

### 5.2 외형 에셋 만들기

1. Project 창에서 **Create > GameSettingTools > Character Skin** 을 고릅니다.
2. 아래 항목을 채웁니다.

| 항목 | 설명 |
|---|---|
| Model Prefab | 외형 모델 프리팹 |
| Animator Controller | 애니메이터 컨트롤러 (비우면 모델에 있던 것) |
| Yaw Offset | 정면이 +Z가 아닐 때 보정할 회전(도) |
| Use Aim IK | 총을 든 가드 외형이면 켭니다 (오른손이 조준 방향을 향함) |
| Fire Animation Events | 애니메이션 이벤트를 받을 곳이 없으므로 **끄세요** |
| Keep Root Bone In Place | 일반(Generic) 모델의 이동 클립을 제자리로 고정합니다 |
| Weapon Grip | 가드 외형의 총 위치 보정 |

3. 맵의 `MapInfo`에서 **Mannequin Skin** 또는 **Guard Skin**에 넣습니다.
   사냥 시간 마네킹 모습을 바꾸려면 **Mannequin Hunt Skin**에 넣습니다. (비우면 Ghoul)

### 5.3 애니메이터 파라미터 규칙

컨트롤러에 아래 이름의 파라미터가 있으면 게임이 자동으로 값을 넣습니다. 없는 파라미터는 건너뜁니다.

| 파라미터 | 형식 | 쓰이는 때 |
|---|---|---|
| `Speed` | Float | 이동 속도(m/s) |
| `MoveX`, `MoveZ` | Float | 몸 기준 이동 방향 (8방향 블렌드용) |
| `Attack` | Trigger | 마네킹 공격 |
| `Shoot` | Trigger | 가드 사격 |
| `Hit` | Trigger | 맞았을 때 |
| `Emote1` ~ `Emote6` | Trigger | 감정 표현 1~6번 키 (또는 `Emote` Trigger + `EmoteId` Int) |
| `Interact` | Bool | 전원 장치를 파괴하는 동안 켜짐 |

감정 표현 애니메이션이 없으면 게임이 간단한 절차적 움직임으로 대신합니다.

> 사냥 외형은 감정 표현·상호작용을 쓰지 않으므로 `Attack`(공격)과 이동 파라미터만 있어도 충분합니다. 기본 Ghoul은 기본·이동 상태 하나와 `Attack` 트리거로 공격 동작을 재생합니다.

> 마네킹 외형은 **가짜 마네킹도 똑같이** 씁니다. 실제와 가짜가 구분되지 않도록, 실제 플레이어만 하는 특별한 동작은 만들지 마세요.

## 6. 모드 설정과 내보내기

### 6.1 모드 설정(Mod Project) 만들기

Project 창에서 **Create > GameSettingTools > Mod Project** 를 고르고 항목을 채웁니다.

**모드 정보**

| 항목 | 설명 |
|---|---|
| Mod Id | 전역 고유 ID. 영문 소문자·숫자·`.`·`_`·`-`, 2~64자. **이름.모드이름** 형식을 권장합니다. (예: `myname.spookymaps`) |
| Mod Name | 로비 모드 화면에 보이는 이름 |
| Version | 모드 버전 (예: `1.0.0`). **고칠 때마다 올리세요.** 버전이 다르면 함께 플레이할 수 없습니다. |
| Author, Description | 만든 사람, 설명 |
| Min Game Version | 필요한 최소 게임 버전. 로비 왼쪽 아래 `v0.6.0-p6-t…`에서 **앞의 숫자 부분**(`0.6.0`)을 적습니다. |
| Dependencies | 필요한 다른 모드 ID ([10장](#10-다른-모드의-에셋-쓰기-의존성)) |

**콘텐츠**

| 항목 | 설명 |
|---|---|
| Maps | 맵 씬 목록 (아래 표) |
| Shared Assets | 다른 모드가 함께 쓸 수 있게 공개할 외형·프리팹 (보통은 비워 둡니다) |
| Strings | 번역 파일 ([8장](#8-번역)) |

**Maps 항목**

| 항목 | 설명 |
|---|---|
| Scene | 맵 씬 |
| Map Key | 맵 ID 뒷부분 (영문 소문자·숫자·밑줄). 전체 맵 ID는 `<Mod Id>.<Map Key>` |
| Display Name | 번역이 없을 때 보이는 맵 이름 |
| Min Players / Max Players | 인원 제한. 0이면 게임 기본값(2~10명) |
| Settings | 맵별 룸 설정 ([7장](#7-맵별-룸-설정과-인원)) |

**내보내기**

| 항목 | 설명 |
|---|---|
| Copy To Mods Folder | 게임의 Mods 폴더 경로를 적으면 내보낸 뒤 바로 복사합니다. 비우면 복사하지 않습니다. |

> **주의:** Copy To Mods Folder를 쓰면 그 폴더 안의 **같은 모드 ID 폴더를 지우고 새로 복사**합니다.

### 6.2 내보내기

1. Project 창에서 Mod Project 에셋을 선택합니다.
2. **GameSettingTools > 모드 제작 > 모드 내보내기 (선택한 Mod Project)** 를 실행합니다.

내보내기는 다음을 차례로 합니다.

1. 맵 씬마다 맵 검사를 합니다. 오류가 있으면 중단하고 오류 목록을 보여 줍니다.
2. 변신 사물 번호를 매기고 씬을 저장합니다.
3. 번들을 Windows용으로 빌드합니다.
4. `mod.json`(번들 지문 포함)과 `strings.csv`를 씁니다.

결과는 `<프로젝트 폴더>/ModExports/<모드 ID>/`에 생깁니다.

```
ModExports/
└─ myname.spookymaps/
   ├─ mod.json
   ├─ myname.spookymaps.scenes.bundle   ← 맵 씬 (맵이 있을 때)
   ├─ myname.spookymaps.assets.bundle   ← 공유 에셋 (Shared Assets가 있을 때)
   └─ strings.csv                       ← 번역 (Strings가 있을 때)
```

이 폴더를 통째로 배포하면 됩니다.

## 7. 맵별 룸 설정과 인원

맵을 고르면 **Value**가 룸 설정에 적용되고, 호스트는 **Min ~ Max** 안에서만 값을 바꿀 수 있습니다.

- 게임이 정한 범위(룸 설정의 원래 범위)를 넘을 수는 없습니다. **두 범위가 겹치는 구간**만 쓰입니다.
- 적지 않은 설정은 게임 기본값과 범위를 그대로 씁니다.
- 가드 수, 목표 횟수 등은 인원에 따른 규칙(가드는 인원의 절반 이하, 전원 장치는 목표보다 많게 등)이 마지막에 한 번 더 적용됩니다.

| 분류 | 설정 이름(Id) | 단위 |
|---|---|---|
| 시간 | `HuntDelay` | 목표 0회일 때 사냥 시간까지의 보호 시간(초) |
| | `PlayTime` | 탐색 단계 시간(초) |
| | `HuntTime` | 사냥 시간(초) |
| 인원·목표 | `GuardCount` | 가드 수 |
| | `ObjectiveCount` | 마네킹이 파괴해야 하는 전원 장치 수 |
| | `GeneratorCount` | 맵에 나오는 전원 장치 수 (전원 장치 후보 수 이하로) |
| | `GeneratorDestroyTime` | 전원 장치 파괴 시간(초) |
| 도구 | `GunCooldown`, `GrenadeCooldown` | 총·수류탄 쿨타임(초) |
| 체력·공격 | `GuardMaxHealth`, `MannequinMaxHealth` | 체력 |
| | `HuntHealthMultiplier` | 사냥 시간 마네킹 체력 배율 |
| | `MannequinAttackRange` | 마네킹 공격 범위(m) |
| | `GunDamage`, `MannequinAttackDamage` | 피해량 |
| 이동 | `GuardMoveSpeed`, `MannequinMoveSpeed` | 이동 속도(m/s) |

예시: 좁은 맵이라 가드를 1~2명으로 제한하고, 탐색 시간을 짧게 하려면 다음과 같이 적습니다.

| Id | Value | Min | Max |
|---|---|---|---|
| `GuardCount` | 1 | 1 | 2 |
| `PlayTime` | 240 | 180 | 360 |

## 8. 번역

맵 이름을 언어별로 보여 주려면 번역 파일을 만듭니다.

1. 텍스트 파일 `strings.csv`를 **UTF-8**로 저장합니다.
2. 첫 줄은 `key,ko,en`이고, 다음 줄부터 `키,한국어,영어`를 적습니다.
3. 맵 이름의 키는 **`mod.<모드 ID>.<Map Key>`** 입니다.

```csv
key,ko,en
mod.myname.spookymaps.basement,버려진 지하실,Abandoned Basement
mod.myname.spookymaps.attic,다락방,Attic
```

- 키가 `mod.<모드 ID>.`로 시작하지 않는 줄은 무시됩니다.
- 쉼표가 들어간 문장은 큰따옴표로 감싸세요.
- 게임에 없는 언어 열은 무시됩니다.
- 번역이 없는 언어에서는 첫 번째 언어(ko)를 보여 주고, 키 자체가 없으면 Display Name을 보여 줍니다.
- 이 파일을 Mod Project의 **Strings**에 넣으면 내보낼 때 함께 복사됩니다.

## 9. 설치와 함께 플레이하기

### 9.1 설치

모드 폴더(`<모드 ID>` 폴더 통째로)를 아래 중 한 곳에 넣습니다.

| 위치 | 경로 |
|---|---|
| 게임 폴더 | `<게임 실행 파일이 있는 폴더>/Mods/` |
| 사용자 폴더 | `%USERPROFILE%/AppData/LocalLow/DefaultCompany/Hide&Freak/Mods/` (게임 폴더에 쓰기 권한이 없을 때) |

- 같은 ID의 모드가 두 곳에 있으면 **게임 폴더 쪽**을 씁니다.
- 로비의 **모드** 화면에서 **모드 폴더 열기**를 누르면 게임 폴더의 Mods가 열립니다.

### 9.2 로비 "모드" 화면

로비 메인 화면 오른쪽 위의 **모드** 버튼을 누릅니다.

| 표시 | 뜻 | 동작 |
|---|---|---|
| `[켜짐]` | 사용 중 | 누르면 끕니다 |
| `[꺼짐]` | 설치되어 있지만 끔 | 누르면 켭니다 |
| `[오류]` | 쓸 수 없음 (아래 줄에 이유) | 누를 수 없습니다 |

- 모드를 새로 넣었으면 **다시 읽기**를 누르세요.
- 켜진 모드의 맵은 룸의 **맵** 설정에서 내장 맵 뒤에 나옵니다.

### 9.3 함께 플레이하기

- **방에 있는 모두가 같은 모드를 켜야 합니다.** 모드 ID, 버전, 파일 내용이 모두 같아야 합니다.
- 다르면 입장할 때 "호스트와 켜진 모드가 달라 들어갈 수 없습니다"라는 안내와 함께 **호스트가 켠 모드 목록**이 표시됩니다. 같은 모드만 켜고 다시 들어오세요.
- 모드는 자동으로 내려받지 않습니다. 모드 폴더를 직접 나눠 주세요.
- 모드를 쓰지 않는 친구와 플레이할 때는 모드를 모두 끄면 됩니다.

## 10. 다른 모드의 에셋 쓰기 (의존성)

여러 맵 모드가 같은 외형이나 사물 프리팹을 쓰게 할 수 있습니다.

1. **에셋 모드**(예: `myname.monsterskins`)를 만듭니다.
   - 공유할 Character Skin·프리팹을 Mod Project의 **Shared Assets**에 넣고 내보냅니다.
   - 맵이 없어도 됩니다.
2. **맵 모드**의 Mod Project **Dependencies**에 에셋 모드 ID를 적습니다.
3. 맵 모드 제작 프로젝트에도 같은 에셋이 있어야 맵에서 참조할 수 있습니다. 같은 프로젝트에서 두 모드를 함께 만드는 것을 권장합니다.

- 플레이어는 두 모드를 모두 설치하고 켜야 합니다.
- 필요한 모드가 없거나 꺼져 있으면 맵 모드가 `[오류] 필요한 모드 '…'가 없거나 꺼져 있습니다.`로 표시됩니다.
- 에셋 모드를 고쳐 다시 내보냈다면 **그 에셋을 쓰는 맵 모드도 다시 내보내세요.** 번들끼리의 참조가 어긋날 수 있습니다.

## 11. 문제 해결

### 11.1 로비 모드 화면의 오류

| 오류 문구 | 원인과 해결 |
|---|---|
| `mod.json이 없습니다.` | 폴더 안에 mod.json이 없습니다. 내보낸 폴더를 통째로 넣었는지, 폴더가 한 단계 더 들어가 있지 않은지 확인하세요. |
| `mod.json을 읽을 수 없습니다` / `형식이 잘못되었습니다` | mod.json을 손으로 고치다 형식이 깨졌습니다. 다시 내보내세요. |
| `모드 ID '…'가 규칙에 맞지 않습니다.` | 영문 소문자·숫자·`.`·`_`·`-`만, 2~64자로 정하세요. 대문자는 쓸 수 없습니다. |
| `다른 Unity 버전 라인(…)으로 만든 모드입니다.` | 게임과 같은 라인(예: 6000.4.x)의 Unity로 다시 내보내세요. |
| `게임(…)보다 새 Unity(…)로 만든 모드입니다.` | 게임 버전 이하의 Unity로 다시 내보내세요. 게임과 같은 버전이 가장 안전합니다. |
| `게임 버전 … 이상이 필요합니다.` | 게임을 업데이트하거나, Mod Project의 Min Game Version을 낮추세요. |
| `번들 파일이 없습니다` | 폴더의 파일이 일부만 복사되었습니다. 폴더를 다시 복사하세요. |
| `맵 ID '…'는 '….'로 시작해야 합니다.` | mod.json을 손으로 고친 경우입니다. 다시 내보내세요. |
| `같은 ID의 모드가 이미 있습니다.` | 같은 모드가 두 폴더에 있습니다. 한 곳에서 지우세요. |
| `필요한 모드 '…'가 없거나 꺼져 있습니다.` | 의존하는 모드를 설치하고 켜세요. |

### 11.2 게임 중 문제

| 증상 | 원인과 해결 |
|---|---|
| 맵이 분홍색으로 보임 | URP가 아닌 셰이더를 썼습니다. 머티리얼을 URP Lit으로 바꾸세요. |
| 가짜 마네킹이 움직이지 않음 | NavMesh를 굽지 않았거나 맵을 고친 뒤 다시 굽지 않았습니다. |
| 플레이어가 바닥·벽을 통과함 | 충돌체가 없습니다. **선택 → 충돌체 추가**를 쓰세요. |
| 마네킹이 맵 밖으로 나감 | 투명 경계·천장이 없거나 틈이 있습니다. |
| 사냥 시간에 맵이 밝게 남음 | MapLight가 아닌 조명이나 구운 조명이 있습니다. **모든 조명 등록**을 다시 실행하세요. |
| 조준해도 외곽선이 안 뜸 | 변신 사물로 등록하지 않았거나, 3m보다 크거나, 충돌체가 없습니다. |
| 변신 모습이 원래와 다름 | 파티클·조명·애니메이션이 달린 물체이거나 정적 배칭이 켜져 있습니다. 맵 검사 경고를 확인하세요. |
| 대기 화면 카메라가 엉뚱한 곳에 있음 | `Map/CameraOverview` 위치를 맞추세요. |
| 친구가 방에 못 들어옴 ("모드가 달라") | 모두 같은 모드·같은 버전을 켰는지 확인하세요. 한 명이라도 모드 파일이 다르면(예: 다시 내보낸 버전) 들어갈 수 없습니다. |

## 12. 배포 전 점검표

- [ ] Unity 버전이 `requirements.txt`의 허용 범위 안이다 (가능하면 게임과 같은 버전)
- [ ] 맵 검사에서 오류가 없고, 경고는 확인했다
- [ ] NavMesh를 마지막으로 고친 뒤에 다시 구웠다
- [ ] 마네킹 스폰 9개 이상, 전원 장치 후보 12개
- [ ] 투명 경계·천장으로 맵 밖에 나갈 수 없다
- [ ] 사냥 시간(어두운 상태)에도 플레이할 수 있다
- [ ] 변신 사물이 충분하고 3m 이하다
- [ ] 씬 이름이 다른 모드·게임 내장 씬과 겹치지 않는다 (이름 앞에 자기 이름 등을 붙임)
- [ ] 모드 버전을 올렸다 (이전 버전과 다른 내용이면)
- [ ] 게임 Mods 폴더에 넣고 직접 한 판 플레이해 봤다
- [ ] 의존하는 모드가 있으면 설명에 적었다

## 13. 참고: mod.json 형식

내보내기 도구가 만들어 주므로 직접 쓸 일은 없습니다. 문제를 찾을 때 참고하세요.

```json
{
    "id": "myname.spookymaps",
    "name": "Spooky Maps",
    "version": "1.0.0",
    "author": "MyName",
    "description": "어두운 지하실 맵",
    "gameVersion": "0.6.0",
    "unityVersion": "6000.4.2f1",
    "dependencies": [],
    "assetBundle": "",
    "sceneBundle": "myname.spookymaps.scenes.bundle",
    "contentHash": "1a2b3c4d5e6f7a8b",
    "maps": [
        {
            "id": "myname.spookymaps.basement",
            "scene": "MyName_Basement",
            "nameKey": "mod.myname.spookymaps.basement",
            "name": "Abandoned Basement",
            "minPlayers": 0,
            "maxPlayers": 6,
            "settings": [
                { "id": "GuardCount", "value": 1, "min": 1, "max": 2 }
            ]
        }
    ]
}
```

| 키 | 설명 |
|---|---|
| `id`, `name`, `version`, `author`, `description` | 모드 정보 |
| `gameVersion` | 필요한 최소 게임 버전 |
| `unityVersion` | 번들을 만든 Unity 버전. 게임과 같은 라인이고 게임 이하여야 합니다. ([2.1](#21-필요-환경)) |
| `dependencies` | 필요한 모드 ID 목록 |
| `assetBundle`, `sceneBundle` | 번들 파일 이름 (없으면 빈 문자열) |
| `contentHash` | 번들 내용 지문. 함께 플레이할 때 같은 파일인지 비교합니다. **번들을 바꾸면 반드시 다시 내보내세요.** 손으로 고치면 친구와 지문이 달라집니다. |
| `maps` | 맵 목록. `scene`은 번들 안 씬 이름, `settings`는 [7장](#7-맵별-룸-설정과-인원) 참고 |
